# 功能规格：课程表同步到系统日历

> 状态：开发中　·　关联 PRD：FR-19（FR-18 是本 FR 的**载体先例**，两者共用同一套日历管道）　·　分支：main
> 接口语义基线：上游 `thu-learn-lib` 的 `getCalendar`（`src/index.ts:286-313`）与 `urls.ts:243-256`；
> 交互参照上游 `robertying/learnX` 的 `screens/CalendarEvent.tsx` 课程表那一段、
> `helpers/event.ts` 的 `saveCoursesToCalendar`。**只取语义，不移植代码**（ADR-0001）。

## 1. 背景与目标

学生最常查的两件时间安排是**作业截止**与**上课**。FR-18 已经把作业截止送进了系统日历；
本 FR 把**课表**也送进去：每天几点在哪上课，以及上课前提醒（默认提前 15 分钟）。

与 FR-18 的关系：**同一套管道**（Calendar Kit 写系统默认日历、按 `identifier` 认领自己的日程、
差量对齐、权限与失败处理），差别只在"数据从哪来"（课表走注册中心接口，不在网络学堂的会话里）
与"事件内容"。故本 spec 只写**增量**，管道细节见 `docs/specs/reminders.md` §3。

## 2. 需求（要什么）

**范围内**：

1. 设置页新增「课程表」一组：
   - **同步课程表到日历**（动作行）：取**未来 4 周**（今天起 27 天，见 §3.4 第 2 条）的课表，
     写进系统日历；再次同步时**增量对齐**（不重复、变了就换）。
   - **研究生课表**（开关，默认关）：关闭时按**本科生**课表取（接口的 `m` 参数分 `bks_`/`yjs_`）。
   - **上课提醒**（开关，默认关，对齐上游 `alarms.courseAlarm` 默认 `false`）：
     打开后同步出来的日程带提醒；**改动后要重新同步才生效**（上游同样如此，界面写明）。
   - **提前多久提醒**（整数分钟，默认 **15**，对齐上游 `courseAlarmOffset ?? 15`）：
     仅在上课提醒打开时出现。
   - **清除已同步的课程日程**（动作行）：把本应用写进日历的**课程**日程全部删掉
     （作业日程不受影响）——这是"课程同步没有总开关"的对应出口（见 §3.4 第 6 条）。
   - **状态行**：上一次同步的结果（成功写了几条 / 失败原因摘要），常驻而非一闪而过。
2. 写入的日程（对齐上游 `saveCoursesToCalendar`）：
   - **标题** = 课程名（上游直接用 `courseName`，不带地点）；
   - **开始/结束** = 该次课的 `日期 + 起止时间`，按**北京时间**换算成绝对时刻（§3.4 第 3 条）；
   - **地点** = 接口给的原样字符串（不做建筑名补全，见"不做"）；
   - **提醒** = 开始时间前 `提前多久` 分钟（上课提醒关着就不设）。
3. 失败如实：网络不可达 / 会话失效 / 接口语义变更 / 解析失败四类按既有口径归因，
   在「课程表」组的状态行里显示**可读原因**（不显示技术细节）；日历权限缺失/写失败同 FR-18 的提示。

**不做（范围外）**：

- **建筑名补全**（上游 `sanitizeLocation` + 242 条 `locationMappings.json`）：只影响日历里地点
  显示的可读性，PRD 没提；先用服务端原样字符串，要的话另开需求（一张 242 条的映射表不该顺手塞进来）；
- **"地点不写入"开关**（上游 `courseEventOmitLocation`）：同上，先不做；
- **日期范围选择器**（上游用 `react-native-paper-dates` 选区间）：接口单次最多 29 天，
  上游默认也是"今天 + 28 天"，故本项目先**固定 4 周窗口**，不做区间选择器（要的话另开）；
- **整个学期的课表**：受 29 天限制需要分多次请求；一次拉一学期会写出几百条日程，
  对"看一眼今天有什么课"是负担。先做 4 周，用户可随时再同步；
- **单双周 / 调课 / 放假**等排课细节：接口给什么就是什么，本项目不推断；
- **作业截止同步**：已在 FR-18 落地。

### 3.4 关键规则

1. **对齐要按"前缀作用域"**（本 FR 顺带修的隐患）：`alignCalendarEvents` 原先把**任何带
   `identifier` 的日程**都当自己的——作业日程与课程日程一旦同处一个日历（现在正是这样），
   一次课程对齐就会把**作业日程全删掉**；更早的隐患是别的应用写的、带 `identifier` 的日程
   也会被误删。故对齐增加 `keyPrefix` 参数：**只看带本前缀的**，其余一律不碰。
   两个前缀：作业 `learnx:`、课程 `learnx-course:`（`'learnx-course:x'` 不以 `'learnx:'` 开头，
   两族互不重叠）。
2. **窗口固定 4 周（今天起 27 天）**：接口单次查询上限 29 天；取 4 周既留出余量，
   条数也控制在"一屏日历能看明白"的量级（本科满课约 20 节/周 → 约 80 条）。窗口由**同步那一刻
   的今天**决定，故每次同步都会把窗口向前滚动——上一窗口里已过的课会被清掉（对齐的作用域内
   删除），日历里留下一段"从现在起 4 周"的课表。
3. **时间按北京时间换算**：接口给的是 `date`（`YYYYMMDD`）与 `startTime/endTime`
   （`HHmm`）这样的**当地时间字符串**，语义是北京时间。设备可能在别的时区（留学生、出国交流），
   故**不用** `new Date(y,m,d,h,min)`（那会按设备时区解释），而是
   **`Date.UTC(y, m-1, d, h-8, min)`** 把它钉成北京时间对应的绝对时刻；写入时另填
   `timeZone: 'Asia/Shanghai'`（对齐上游）。这样"8:00 的课"在任何时区的设备上都指向同一时刻。
4. **重新同步是增量**：同一窗口内，未变的日程留着、变了的删了重建、多出来的删掉。
   不做"先删区间再全建"（上游那套会让日历在同步瞬间整片闪一下，且丢掉"哪些是新的"的信息）。
5. **上课提醒改动后需重新同步**：提醒是写在日程上的，改了提前量不会自动重写已写好的日程。
   界面在「上课提醒」「提前多久」旁写明这一点（对齐上游的提示），状态行也会显示上次同步时间。
6. **"清除课程日程"是课程侧的出口**：课程同步没有总开关（上游也没有），故给一个动作行，
   把带课程前缀的日程全部删掉；作业日程不受影响（前缀作用域保证）。
7. **课表对个别课程缺字段不整批失败**：单条缺日期/时间就跳过该条（课表里出现残缺行时，
   不该让整个同步失败）——但要**记日志**，便于判断是接口变结构还是个别脏数据。

## 5. 验收标准

**自动化可验证（单元测试，不依赖设备）**：

1. JSONP 解析：`name([...])` 取出数组；前缀不符 / 括号不配对 / 内层不是数组 / 内层不是合法 JSON
   → 抛"解析失败"；空数组是合法结果。
2. 字段映射：`nr/nq/kssj/jssj/dd` 按上游映射；缺日期或缺起止时间的条目**跳过且不整批失败**。
3. 北京时间换算：`20260929 + 0800` 换算成 `2026-09-29T00:00:00Z` 对应的时刻
   （与 `Date.UTC(2026,8,29,0,0)` 相等），**与运行设备的时区无关**（用例里同时用
   `Date.UTC` 反算，不依赖本地时区）；非法日期（`20261332`）或非法时间（`2560`）→ 跳过。
4. 日程计划：标题 = 课程名；起止 = 该次课的时间；`reminderMinutes` = 提前量（上课提醒关时为
   `null`）；键 = `learnx-course:<日期><起始时间>:<课程名>`（同一天同一时刻同一门课只有一条）。
5. 前缀作用域对齐：`alignCalendarEvents(desired, existing, 'learnx-course:')` **不碰**带
   `learnx:` 前缀的作业日程、也不碰没有前缀的日程；期望集合为空时只删带课程前缀的。
6. 静态门：`check arkts`（主 + 测试显式传路径）、`check lint` 零错误；`build` 成功；
   `check-l10n` 键集合一致。

**设备验收（模拟器 learnx / HarmonyOS 6.1.1(24)，已登录真实账号，2026-09-28）**：

> 结论：**第 7–12 项全部通过**（含跨主机三步取数、幂等、研/本切换、清除不误伤作业日程）。
> 过程中抓出并修掉一个**真缺陷**（见下），另有一条未验项（到点弹出，与 FR-18 同一个）。

7. ✅ 设置页出现「课程表」组：同步行、研究生课表、上课提醒、清除行、说明行与状态行齐备；
   开关状态**重装/重启后仍在**（首屏状态行显示"尚未同步过"）。
8. ✅ 点「同步课程表到日历」：日志 `课表取毕 20260929~20261026 研究生=false 原始=40 可用=40`
   → `课程日程对齐完成 新增=40 期望=40`；状态行显示 `已同步 40 条课程日程`。
   **跨主机三步都通了**（工单 36 字符、注册中心会话已建立、JSONP 5362 字符非 HTML）。
9. ✅ **幂等**：紧接着再同步 → `课程日程已是最新，无需变更 期望=40`。
   开「上课提醒」后再同步 → `新增=40 删除=40`（40 条全部重建以带上提醒），
   「提前多久提醒」行随之出现、状态行仍正确。
10. ✅ 切「研究生课表」后同步 → `研究生=true 原始=0 可用=0`（本账号是本科生，研究生课表为空）
    → `删除=40 期望=0`；切回本科再同步 → `新增=40` 恢复。
11. ✅ 「清除已同步的课程日程」→ `新增=0 删除=40 期望=0`、状态行变 `已同步 0 条`；
    **随后触发作业侧对齐仍是 `日历日程已是最新，无需变更`**——课程同步、研/本切换、清除
    这三轮共删掉 80 余条课程日程，**作业日程一条都没被碰到**（前缀作用域的直接验收）。
12. ✅ 失败面（**验于真实故障**）：修好之前，第二次同步就是失败的——
    当时日志给出的是可读的 `AUTH_FAILED`（而不是误导性的"解析失败"），
    且**已有日程一条没动**（对齐只在拿到完整数据后才动手）。

**修掉的真缺陷（2026-09-28，实测抓出）**：注册中心**自己那一份 `JSESSIONID` 若还在，
第②步票据认证会直接返回登录页 HTML**——会话建立不起来，第③步拿回 HTML、解析失败，
表现为"**只有第一次同步成功，之后再也拉不到课表**"。修法：认证前把**该主机自己的**
`JSESSIONID` 置过期（值若与学堂的相同则说明是同一份域 Cookie，**不清**，否则会连带登出学堂）。
修后连续两次同步均成功，且"清掉旧会话 → 认证 → 建起新会话"的事实全程可见。

**需用户确认**：第 10 项的**真机**表现（本机账号是本科生，研/本差异只验到"研究生课表为空"）；
以及"课表写进系统日历、提醒由系统日历弹出"这一形态是否符合预期。
**到点弹出**与 FR-18 是同一个未验项，见 `docs/specs/reminders.md` §6。
