# 功能规格：文件下载管理（进度 · 目标目录 · 重试）

> 状态：已实现（自动化验收已过；设备项待用户统一验收）　·　关联 PRD：FR-10（与 FR-08 / FR-16 的边界见 §2）　·　分支：main
> 接口语义基线：上一批（FR-08）已在 `repository/fileRepository.ets` 打通"取字节 → 落盘"，
> 本 FR 在它之上加**可观测与可控制**的部分。交互参照上游 `robertying/learnX` 的
> `helpers/fs.ts`（下载与进度回调）与 `screens/Settings.tsx`（目录相关设置项）。

## 1. 背景与目标

FR-08 交付了"能下能开"，但对用户是**黑盒**：不知道下了多少、下到哪、失败了怎么办。
FR-10 把下载变成可管理：**看得见进度、知道文件在哪、失败能重试**。
这是 PRD §6 第 2 项实机验收里"下载并打开一个课件文件"的体验前提。

## 2. 需求（要什么）

**范围内**：

1. **进度**：下载中显示百分比（或进度条），不再只有"下载中…"；
2. **目标目录**：用户可选择下载落到**应用文件目录**（documentDir，随应用数据保留）
   还是**缓存目录**（cacheDir，系统空间紧张时可回收）。默认缓存目录——FR-08 的现状即是缓存，
   改默认值会让已下的文件"找不到"；
3. **重试**：失败的下载可重试，不必先退出页面；重试**覆盖**旧的半截文件；
4. **已下载可见**：详情页显示"已下载"与文件大小；提供"重新下载"（强制刷新）。

**不做（属其他 FR）**：

- **下载列表 / 下载中心页**：PRD 无此需求，不做（进度与按钮都在文件详情页内）；
- **断点续传**：PRD 无此需求，不做（课件体积小，重下成本低）；
- **后台下载**：属 FR-25（P2），不做；
- **分享**：属 FR-23（P2），不做。

## 3. 设计（怎么做）

### 3.1 上游事实（对照基线，逐行核过）

| 事实 | 出处 |
|---|---|
| 下载目标目录由设置决定：`fileUseDocumentDir` 为真取文档目录，否则取缓存目录，其下再建 `learnX-files` | `helpers/fs.ts:41-46` |
| 文件名可省略课程名前缀（`fileOmitCourseName`） | `helpers/fs.ts:55-62` |
| 进度来自**下载回调**：iOS 用 `bytesWritten/contentLength`，Android 用 `totalBytesWritten/totalBytesExpectedToWrite`，并 `toFixed(2)` 归一成 0~1 | `helpers/fs.ts:79-140` |
| 失败判据与清理：状态码非 200 / 写入 0 字节 / 内容含 `location.href` → **删除文件并抛错** | `helpers/fs.ts:100-160` |
| 详情页头部有"刷新下载"按钮（强制重下） | `FileDetail.tsx:147-160` |

### 3.2 模块与文件

| 模块 | 文件 | 职责 |
|---|---|---|
| `network` | `learnClient.ets`（改） | 下载时通过 `request.on('dataReceiveProgress')` 上报进度：新增可传回调的下载入口 |
| `storage` | `preferenceStore.ets`（改） | 新增"下载目录选择"这一偏好的读写（与应用级偏好同一入口） |
| `native` | `fileAdapter.ets`（改） | 除 `cacheDir` 外提供 `documentDir` 的文件根；按选择给出根目录 |
| `repository` | `fileRepository.ets`（改） | 目标目录按偏好计算；下载转发进度回调 |
| `viewmodel` | `fileStore.ets`（改） | 下载状态里加**进度百分比**（0~100）与失败原因；重试入口 |
| `pages` | `FileDetail.ets`（改） | 进度条 + 百分比文字；"重新下载"；失败时"重试" |
| `pages` | `Settings.ets`（改） | 目标目录二选一（与 FR-16 的设置页共用同一页；本 FR 只加这一项） |

### 3.3 关键规则

1. **进度必须有文字**：`ProgressBar` 属 ArkUI 组件，可进节点树；但**同时给出百分比文字**
   （"下载中 42%"），以便在节点树里可验收（陷阱 7 的教训：只有图形没有文字就无法验收）。
2. **进度来源单一**：进度只在网络层产生（`dataReceiveProgress`），经 store 传到页面；
   页面不得自行估算（估算出来的"进度"在慢网络下会倒退，比没有更糟）。
3. **内容长度不可得时不给百分比**：服务端未给 `Content-Length` 时显示"下载中…"而不是 0% 或
   假的 100%。**不猜**。
4. **重试要覆盖**：重试前不删旧文件也必须是覆盖写（FR-08 已用 `TRUNC`），避免拼出损坏文件。
5. **改目录不搬旧文件**：切换目标目录只影响**后续**下载；已下的文件留在原处，
   详情页的"已下载"判定要能同时看两个目录（否则用户切目录后会看到"未下载"，
   而文件其实还在）。
6. **失败原因分四类**（对齐 NFR-NET）：网络不可达 / 会话失效 / 接口语义变更 / 解析失败，
   与既有 `FailReason` 一致；页面只显示分类文案，细节进日志。

> 实现期的三处判断，在此留痕：
> ① 进度条用 `Progress({ type: ProgressType.Linear })`，并**同时给出百分比文字**——
> 图形不进 UI 节点树，只有文字才能验收；
> ② 进度事件很密，`fileStore` 只在**整数百分比变化**时通知，避免页面反复重建；
> ③ "打开"多了两步兜底：先按两个目录找**已存在的**文件，找到就直接打开、不重下
> （否则切过目录后会重复下载一份）。

## 5. 验收标准

**自动化可验证（单元测试，不依赖设备）**：

1. 进度归一：`已写/总量` → 0~100 的整数；总量为 0 或缺省时**不给百分比**（状态为"未知进度"）；
   总量小于已写（服务端给错）时不产生 >100 的值；
2. 目标目录选择：偏好值为文档目录时取 documentDir 下的根，缓存目录时取 cacheDir 下的根；
   偏好缺失/非法时退让为**缓存目录**（与 FR-08 行为一致）；
3. "已下载"判定能同时看两个目录；
4. 静态门：`check arkts`（主 + 测试显式传路径）、`check lint` 零错误；`build` 成功；`check-l10n` 一致。

**设备验收（模拟器/真机，已登录）**：

5. 下载一个课件：进度条与百分比**随下载增长**，完成后变为"已下载"；
6. 点"重新下载"：进度从 0 重新走一遍，且不出现文件损坏（能正常打开）；
7. 下载失败（如会话失效或断网）后点"重试"能成功；
8. 在设置里把目标目录切到文件目录后再下载：文件落在文件目录下（重启后仍在）；
9. **需用户确认**：PRD §6 第 2 项"下载并打开一个课件文件"这一环的完整体验。
