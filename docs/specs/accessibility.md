# 功能规格：无障碍适配（读屏可理解、触摸目标、大字号不破版）

> 状态：开发中　·　关联 PRD：FR-30　·　分支：main
> 上游 `robertying/learnX`：**全库检索无 `accessibility*` 使用**，即上游也没做无障碍。

## 1. 背景与目标

本项目**此前一处无障碍属性都没用过**（`accessibilityText`/`accessibilityLevel`/`accessibilityGroup`
在全库 grep 命中数为 0）。三个具体缺口：

1. **有些控件读屏念不出名字**：头部那排「搜索」是 `Button() { Image(...) }`——纯图标按钮，
   没有文字，读屏只念"按钮"；用户不知道它是干什么的；
2. **装饰性图标会被念出来**：设置页每行右侧的 `chevron_right`、空态/错误态的图标，
   都是装饰，念出来只是噪音；
3. **固定行高在大字号下会截断**：设置页与个人信息页的行写死 `height(56)`，
   而行里是 16fp 的文字——系统字号调到 1.75 倍时文字约 34vp，加上内边距会超出 56vp 被裁掉。

另外 `SymbolGlyph` **不进 UI 节点树**（本项目已踩过），所以"图标有没有"不能靠节点树验：
这次给图标补无障碍语义，也顺便让它的可读性有据可查（见 §5）。

## 2. 需求（要什么）

**范围内**：

1. **无文字的可点控件必须有可读名称**：头部搜索按钮补 `accessibilityText`；
2. **可点目标不小于 40vp**：上述按钮当前实际约 28vp（20 图标 + 2×4 内边距），提到 40vp；
3. **装饰性元素标 `accessibilityLevel('no')`**：行尾箭头、空态/错误态图标、骨架的灰条
   ——它们不承载信息，念出来只干扰；
4. **加载骨架整体给一句可读文本**：骨架在视觉上是灰块、在无障碍里应当是"正在加载"，
   而不是一片沉默（沉默会让读屏用户以为界面是空的）；
5. **文本不被固定行高裁掉**：把承载文字的固定 `height` 改成 `minHeight`（最小高度保留版式，
   字号变大时行跟着长）。

**不做（范围外）**：

- **不做列表行的 `accessibilityGroup`**：把"标题+摘要+元信息"合成一个可读条目在道理上是对的，
  但它会**改变 UI 节点树的形态**——而节点树是本项目唯一可用的验收手段（截图在我这里只是
  原始图像数据）。在**无法验证读屏实际效果**的前提下动掉自己的验收手段，是拿不可验证换不可验证；
  等用户设备上能真听一遍时再做，那时也才知道合成到什么粒度合适。
- **不做字号缩放的自定义实现**：ArkUI 的数值 `fontSize` 单位就是 **fp**（随系统字号缩放），
  系统已经在缩放，应用不该再造一套；本 FR 只保证"缩放后不被裁"。
- **不做读屏的完整遍历审计**（逐个页面核对朗读顺序、焦点顺序）：需要真机 + 读屏，
  属"等设备"的部分（§5 第 4 条）。
- **不做对比度专项检查**：现有配色来自 ADR-0003 的语义色，深色/浅色两套已存在；
  对比度的问题若真有，应连同配色一起评审，不在本 FR 里改。

## 3. 设计（怎么做）

### 3.1 上游事实（对照基线）

| 事实 | 出处 |
|---|---|
| 上游全库无 `accessibility*` 用法 | `src/` 检索 |
| 上游用 `IconButton`/`TextButton` 承载图标与文字，图标按钮同样没有无障碍名称 | `src/components/IconButton.tsx` |

> 与上游的**有意不同**：本项目补上可读名称与触摸目标——这类改动不做也不影响功能，
> 但做了才有"看得见之外，也听得见"。

### 3.2 模块与文件（全部是就地补属性，无新模块）

| 文件 | 改什么 |
|---|---|
| `pages/Notices.ets` / `Files.ets` / `Assignments.ets` / `Courses.ets` / `Settings.ets` | 搜索按钮：`accessibilityText` + 内边距 4→10（触摸目标 40vp） |
| `pages/Settings.ets` | 行尾箭头 `accessibilityLevel('no')`；14 处 `height(56)` → `constraintSize({minHeight: 56})` |
| `pages/Profile.ets` / `pages/SemesterSelection.ets` | 同上（行高与装饰图标） |
| `components/StateView.ets` | 空态/错误态图标标装饰 |
| `components/Skeleton.ets` | 整块给 `accessibilityText(加载中…)`，灰条标装饰 |

> 没有 `common/` 纯逻辑模块：本 FR 改的都是**平台属性**（可读名称、层级、布局约束），
> 没有可枚举的纯函数，故不新增单测——这一点如实记在 §5。

### 3.3 关键规则

1. **`accessibilityText` 用既有文案键**（搜索用 `SEARCH_TITLE`、骨架用 `STATE_LOADING`）：
   不新增文案键，也就不会漏翻英文；
2. **装饰用 `'no'` 而不是 `'no-hide-descendants'`**：前者是"这个组件本身不可识别"，
   后者会连子节点一起藏掉——对图标按钮那种"图标是唯一内容"的场景，用后者会把整个按钮
   变得不可识别，与第 1 条正好相反；
3. **触摸目标用内边距凑到 40vp**，不改图标尺寸：图标的视觉大小是设计选择，
   这里只扩大命中区域；
4. **`minHeight` 而不是删掉高度**：行高是版式的一部分（行与行的节奏），
   `constraintSize({minHeight})` 保住了版式，又允许内容变高。

## 5. 验收标准

**自动化（已过）**：

1. 静态门：`check arkts` 主 101 / 测试 28 文件 0 error、`check lint` 0 error、`build` 成功、
   **297 例单测 0 失败**、`check-l10n` 一致（base/en_US 209 键）；
2. **无新增单测**：本 FR 改的都是平台属性（可读名称 / 层级 / 布局约束），没有可枚举的纯函数
   ——如实记录，而不是硬凑用例。

**设备验收（模拟器 learnx，2026-09-29）**：

3. ✅ **触摸目标真的变大了**（节点树直接量得出）：搜索按钮 `bounds=[1060,752,1200,892]` →
   **140×140px = 40×40vp**（改前是 98px＝28vp）；同行的筛选「全部/未读」与「刷新」
   本来就是 **211×140px = 60×40vp**，可见 40vp 正是本项目事实上的下限，改后与它们齐平；
4. ✅ **版式无回归**：设置页三行主题项的中心间距仍为 **196px = 56vp**
   （`跟随系统` 902 → `浅色` 1098 → `深色` 1294，两两相差 196），
   即正常字号下 `constraintSize({minHeight: 56})` 与原来的 `height(56)` 表现一致；
   通知列表项照常渲染（同一份节点树里能查到列表内容）；
5. ✅ 装机运行正常（`Smoke: PASS`），四个内容页与设置页均可正常进入。
6. ⚠️ **两件事本机无法判定，如实标未验**：
   - **`accessibilityText` 不进这个节点树**：搜索按钮的 `text` 在 dump 里仍是空的
     （实测），所以"读屏会念出名字"这条**没有设备证据**，只有代码；
   - **读屏实际朗读与焦点顺序**、**系统字号调大后的观感**，都需要真机 + 系统读屏/字号设置。

## 6. 风险 / 待定

| 项 | 说明 | 处置 |
|---|---|---|
| 触摸目标变大可能挤动头部版式 | 搜索按钮 +12vp（28→40） | 设备验收第 3、4 条专门量这个：按钮 bounds 变宽、同行其他控件位置不重叠 |
| `minHeight` 改动影响行高观感 | 正常字号下行为应与 `height(56)` 完全一致（内容不超 56 时取 56） | 验收第 4 条用节点树量行高，仍是 56vp 才算通过 |
| 读屏与字号两条要真机 | 模拟器没有读屏可驱动、我也无法判断画面 | 与 FR-24/FR-26 一起等用户设备；本 FR 已把**代码层面**能做的做完 |
| 列表行未做 `accessibilityGroup` | 见 §2 范围外 | 等能真听读屏时再定分组粒度 |
