# 功能规格：列表筛选与排序（四个维度通用）

> 状态：已实现（自动化验收已过；设备项待用户统一验收）　·　关联 PRD：FR-12　·　分支：main
> 交互参照上游 `robertying/learnX` 的 `components/FilterList.tsx`、`components/Filter.tsx`；
> 排序规则见各维度自己的 spec（本文件不重复，只在 §3.3 汇总指向）。

## 1. 背景与目标

前四个维度（通知/作业/文件/课程）各自先立了起来，筛选是**各写各的**：通知与作业各有一行
筛选按钮，文件没有；将来第四个维度再加一遍就是第四份拷贝。FR-12 把"筛选"收成**一份通用组件**，
并补上**文件按分类筛选**——这条在 files spec 里被显式推迟到本 FR（数据那时就有了：分类名已随列表取回）。

## 2. 需求（要什么）

**范围内**：

1. **通用筛选组件**（`components/FilterBar.ets`）：一行可横向滚动的选项按钮，选中态高亮；
   选项的文字可以是**文案键**（通知/作业）或**字面量**（文件分类名来自服务端数据）；
2. 通知：全部 / 未读（保持现状，改用通用组件）；
3. 作业：未完成 / 已完成（保持现状，改用通用组件；默认"未完成"）；
4. **文件：按分类筛选**（新增）——选项为"全部"加上**当前可见范围内实际出现过的分类名**；
5. 筛选状态**仍是各视图自己的页面本地状态**（通知那次实测踩到"放进 store 会让两个视图互相串"）；
6. 排序：保持各维度既有规则（§3.3 汇总），本 FR 不改动排序行为。

**不做（属其他 FR，或本批不做）**：

- **收藏 / 归档 / 隐藏筛选**：上游有，但 **PRD 里没有这三条需求**——属镀金，不做；
- **课程拖动排序**：上游用 `setCourseOrder` 做拖动排序，PRD FR-09 只要求"列表、详情"，
  且拖动交互属打磨（FR-29），不做；
- **搜索**：属 FR-17（P2）。

## 3. 设计（怎么做）

### 3.1 上游事实（对照基线）

| 事实 | 出处 |
|---|---|
| 上游把四个维度的筛选收在一个 `FilterList` 里，按 `type` 分派可用的筛选项 | `components/FilterList.tsx:47-115` |
| 筛选项取自 `settings.tabFilterSelections[type]`（**全局持久化**的每维度筛选记忆），缺省回落到 `defaultSelected` | `FilterList.tsx:79-84` |
| 作业默认选中 `unfinished`；其余维度默认 `all` | `screens/Assignments.tsx:121`、`FilterList.tsx:81` |
| 上游**没有排序 UI**：各维度的顺序由 actions 里的固定排序规则决定 | 全局 grep `sortBy`/`setSort` 无命中 |
| 课程排序靠拖动 + 服务端 `sortCourses`（属课程维度，不在本 FR） | `data/actions/courses.ts`、`index.ts:1011-1030` |

### 3.2 模块与文件

| 模块 | 文件 | 职责 |
|---|---|---|
| `components` | `FilterBar.ets`（新） | 通用筛选条：一组选项（文字可为文案键或字面量）+ 选中值 + 选择回调 |
| `viewmodel` | `fileStore.ets`（改） | `visibleFor` 增加分类参数；新增"可见范围内的分类名列表" |
| `pages` | `Notices.ets` / `Assignments.ets` / `Files.ets`（改） | 改用自己的通用筛选条；文件加分类筛选 |

### 3.3 关键规则

1. **筛选状态留在页面本地**，不放进 store：一个应用级 store 只有一份数据，两处视图（标签页与
   课程详情页签）共用时，筛选放进去会互相串（通知那次实测踩到，见 notices spec §5.2）。
   **与上游的差异**：上游把每维度的筛选记忆持久化到设置里（`tabFilterSelections`）；
   本项目不持久化——PRD 无此要求，且"上次筛选被记住"在聚合页与单课页签共用时正是串台的来源。
2. **文件分类筛选项来自数据本身**：只列出当前可见范围内**实际出现过**的分类名，
   不列空分类（选了必然为空的分组是假动作）。分类名去重后按名称排序，保证顺序稳定。
3. **筛完为空 ≠ 错误**：空态与错误态继续分开（沿用三态规则）。
4. **排序不变**：通知按发布时间倒序、作业按"未截止在前/已截止在后"、文件按上传时间倒序、
   课程按服务端顺序——各自的规则与测试在各自 spec 与 model 里，本 FR 不重写。

## 5. 验收标准

**自动化可验证（单元测试，不依赖设备）**：

1. 分类名列表：从文件列表里取出去重、非空、按名称排序的分类名；
2. 分类过滤：给定分类名时只留该分类的文件；空串表示"全部"（不过滤）；
   过滤后再排序的结果与不过滤时同序（顺序稳定）；
3. 静态门：`check arkts`（主 + 测试显式传路径）、`check lint` 零错误；`build` 成功；`check-l10n` 一致。

**设备验收（模拟器/真机，已登录）**：

4. 通知/作业的筛选外观与点击行为与切换前一致（这是纯替换，不该有回归）；
5. 文件列表出现"全部 + 各分类"筛选条；选某个分类后只剩该分类的文件，选"全部"恢复；
6. 聚合标签与课程详情页签的筛选**互不影响**（各自本地状态）；
7. 筛完为空时显示空态而不是错误态。

## 6. 风险 / 待定

| 项 | 说明 | 处置 |
|---|---|---|
| 分类很多时筛选条过长 | 课程文件分类通常个位数，但极端情况可能很多 | 筛选条横向可滚动；不做下拉菜单（无需新增交互范式） |
| "排序"在 PRD 里与"筛选"并列 | 上游无排序 UI，PRD 也未给出排序项清单 | 本 FR 把"排序"读作**各维度既有的排序规则**（§3.3 第 4 条），不新增排序 UI；若用户期望的是"可选排序"，按需求登记另开 |
| 与 FR-16 的关系 | 上游把筛选记忆放进设置页持久化 | 本项目不持久化（规则 1）；FR-16 也不放这一项 |
