# 功能规格：版本更新检查与更新日志（FR-28）

> 状态：**已交付一半，剩下的一半按用户决定终止**（2026-09-29）　·　关联 PRD：FR-28　·　分支：main
> 交互参照上游 `robertying/learnX`：上游**没有**更新检查（发到应用商店，更新交给商店）。

## 1. 背景与目标

两件事：
1. 用户想知道**这一版改了什么**——现在只能去翻仓库；
2. 用户想知道**有没有新版本**——现在只能自己去 GitHub 看。

## 2. 需求（要什么）

**范围内**：

1. **内置更新日志页**：设置页新增「更新日志」，把打包进包里的 `CHANGELOG.md`
   渲染成**可读的**排版（标题/列表/加粗/代码/链接），而不是让用户看 Markdown 源码；
2. **「检查更新」= 打开项目的发布页**（交给系统浏览器）：用户在浏览器里（通常已登录）看有没有新版本；
3. **读不到日志不白屏**：资源缺失时给一句明确的空态；
4. **点不开浏览器要提示**：设备上没有能处理链接的应用时给提示（模拟器上就是这种情况）。

**不做（范围外）——这是本 FR 最要紧的一段，理由写在下面**：

- **不做"应用内自动比对版本号"**。**（用户 2026-09-29 拍板：不做）**
  应用要自动比对，就得读自己仓库的 releases，
  而**本仓库是 private**：2026-09-29 实测，匿名请求
  `https://api.github.com/repos/HanyuNol/learnX-harmony/releases/latest` 返回 **`http=404`**
  （网络本身通，1.2s 拿到响应；404 是 GitHub 对匿名客户端隐藏私有仓库的方式）。
  要让这条路走通，只有两种可能：
  1. **把仓库转为公开**——这是仓库可见性的决定，**属用户**（涉及把源码公开）；
  2. **往安装包里塞一个访问令牌**——那是**凭据进产物**，本项目明令不做
     （`SECURITY.md`；装出去的应用里带着一个能读私有仓库的令牌，泄漏即失控）。
  故本 FR 采用**不需要凭据、与仓库可见性无关**的做法（§2 第 2 条）。
  将来若仓库转公开，补一个"读 releases 比版本"的增量即可——`native/updateAdapter` 是唯一要动的地方。
- **不做应用内下载/安装新版本**：鸿蒙侧安装要经系统（`AppGallery` / 应用市场），
  应用自己拉起安装属越权；且本应用的目标分发路径本来就是应用市场内测（`OPERATIONS.md` §9）。
- **不做"忽略此版本 / 只提醒一次"**：没有自动比对，就没有"提醒"可忽略。
- **不做把 CHANGELOG 全文作版本比对**：那是拿文档当接口用，误报（措辞变化）比收益多。

## 3. 设计（怎么做）

### 3.1 上游事实（对照基线）

| 事实 | 出处 |
|---|---|
| 上游没有更新检查，也没有更新日志页（它发到应用商店，更新由商店负责） | `src/` 全库检索无相关实现 |
| 上游"关于"页只显示版本号 | `src/screens/Settings.tsx` 一带 |

> 与上游的**有意不同**：本项目是"自建分发 + 私仓"，用户拿不到商店的更新提示，
> 所以要给一条自己能走的确认路径（§2 第 2 条）。

### 3.2 模块与文件

| 层 | 文件 | 职责 |
|---|---|---|
| `common` | `markdown.ets`（新） | **纯逻辑**：最小 Markdown → HTML（可穷举测试） |
| `native` | `changelogAdapter.ets`（新） | 读包内 `CHANGELOG.md`（读不到返回空串） |
| `native` | `updateAdapter.ets`（新） | 「检查更新」的出口：把发布页交给系统浏览器（URL 只在这里一份） |
| `pages` | `Changelog.ets`（新） | 更新日志页：Markdown → HTML → 复用 `RichTextView` |
| `pages` | `Settings.ets`（改） | 两行入口：更新日志 / 检查更新 |
| `pages` | `Main.ets`（改） | 新增 `changelog` 目的地分派 |
| `components` | `RichTextView.ets`（改） | 新增 `fillHeight`：长文档独占高度、内部滚动 |
| 脚本 | `scripts/sync-changelog.mjs`（新） | 仓库根 `CHANGELOG.md` → `resources/rawfile/` |

### 3.3 关键规则

1. **rawfile 里那份是构建产物**：真源是仓库根的 `CHANGELOG.md`，由脚本同步（发版前必跑，
   见 `OPERATIONS.md` §7.4b）。漏跑**不报错**，只表现为"日志少了一段"，故与 `sync-version.mjs`
   同列进验收门。
2. **Markdown 解析只支持自己用的那一小撮**（标题/列表含一层缩进/段落/加粗/行内代码/围栏代码块/
   引用/分隔线/链接）：架构不变量 §2 禁第三方解析库，而变更日志的语法是有限且已知的。
   不认识的构造**当普通文本**（宁可朴素，不可丢失）。
3. **解析结果仍要过清洗器**：`markdownToHtml` 自己先转义 `<`/`>`/`&`，输出的 HTML 再经
   `sanitizeHtml` 白名单——两道防线，且链接只认 `http(s)`。
4. **长文档用 `fillHeight`**：默认的自动高度有上限（6000vp），超了会变成"内层 Web 滚动"；
   这一页**就是**这篇文档，故让它独占高度自己滚，避免内外两层滚动条。
   实测该文档量得 **28117** CSS px——远超上限，正是不做 `fillHeight` 会踩的坑。
5. **"检查更新"不碰网络**：只 `startAbility(VIEW_DATA)` 交给浏览器；失败（设备上没有浏览器）
   如实提示，不静默。

   （`<script>` 只显示为文本）、`&` 转义、未闭合围栏收尾、空输入；
2. 静态门：`check arkts` 主 99 / 测试 27 文件 0 error、`check lint` 0 error、`build` 成功、
   **293 例单测 0 失败**、`check-l10n` 一致（base/en_US 208 键）。

**设备验收（模拟器 learnx / 真实账号，2026-09-29）**：

3. ✅ 设置页出现「更新日志」「检查更新」两行（节点树可定位）；
4. ✅ 进「更新日志」：日志 `[richText] 正文渲染完成 高度=28117 公式数=0`；
   节点树里出现 **`TitleBar = 更新日志`** 与来自 Web 的**结构化节点**——
   `heading`（`变更日志`、`未发布`、`变更`）、`link`（`Keep a Changelog`、`语义化版本`）、
   `listMarker`（`•`）、`paragraph`、`code`、`staticText`（正文内容与刚写的 FR-29 条目）。
   即：**Markdown 真的排成了富文本**，不是源码原样显示；
5. ✅ 点「检查更新」：AMS 解析隐式意图 → `ability:MainAbility, bundle:com.huawei.hmos.browser`
   → `HWBR-BrowserService: call fixupUrl` → `RequestFromHttpDns … domains=github.githubassets.com`
   ——**系统浏览器确实起来了并去加载 GitHub**（`githubassets` 是 GitHub 的静态资源域）。
   > 私仓带来的**已知限制**（不是缺陷）：浏览器里若不是登录态，看到的是 404。
   > 这正是 §2 把"自动比对版本"列为不做的那条约束的同一根因。
6. ⚠️ 设备上没有浏览器时的**失败提示**：模拟器上装了浏览器，这条降级路径**没构造出来**
   （代码路径是 `startAbility` 抛错 → Toast）。

## 6. 风险 / 待定

| 项 | 说明 | 处置 |
|---|---|---|
| 私仓 → 浏览器里可能看到 404 | 用户未登录 GitHub 时，发布页就是 404 | 已知限制；仓库若转公开即消失。**是否转公开由用户决定**（§2） |
| rawfile 副本可能过期 | 漏跑 `sync-changelog.mjs` | 已写进验收门（`OPERATIONS.md` §7.4b）；漏跑只表现为日志少一段，不影响可用性 |
| Markdown 解析的覆盖面 | 只支持本项目自己用的构造（§3.3 第 2 条） | 变更日志若引入新语法（如表格），需要在 `markdown.ets` 里补并加用例；不补也只是"朴素显示" |
| 更新日志很长（2 万字符） | 一次性渲染整篇 | 实测 28k px 的文档渲染与滚动正常；若将来日志继续膨胀，考虑只显示最近 N 个版本段 |
