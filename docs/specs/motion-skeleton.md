# 功能规格：动效与骨架屏打磨（列表加载态 + 标签切换过渡）

> 状态：开发中　·　关联 PRD：FR-29　·　分支：main
> 交互参照上游 `robertying/learnX` 的 `components/Skeleton.tsx`。**只取语义，不移植代码**（ADR-0001）。

## 1. 背景与目标

两处观感缺口：

1. **列表的加载态是"居中转圈 + 加载中…"**。列表的等待感来自"不知道要等多少东西"，
   而转圈对"马上会出现一列内容"这件事一个字都没说。四个内容列表页（通知/作业/文件/课程）
   共用 `loadingView()`，一起改就一起好；
2. **切底部标签没有过渡**。`Tabs.animationDuration` 未设置时**平台默认是 0**（官方文档：
   *When this property is not set or set to null, the default value is 0*），也就是硬切。

## 2. 需求（要什么）

**范围内**：

1. **四个内容列表页的加载态改成骨架占位**：按真实行的形状摆出若干行灰条
   （标题 / 摘要 / 元信息三根，高度分别对齐 16 / 14 / 12 号字），行数够铺满首屏（6 行）；
2. **骨架带"呼吸"**：整块在 1 ↔ 0.5 之间往返淡入淡出（与上游 `Skeleton.tsx` 同一语义：
   上游是 `Animated.sequence` 500ms 一来一回、循环），让人看得出"在等"而不是"卡住"；
3. **只有列表页用骨架**：详情页、学期选择页那种"一次一个动作"的等待保留居中转圈
   （骨架要有"行"才成立，摆在没有行的地方就是骗人）；
4. **标签切换给 200ms 过渡**（把平台的 0 显式改掉），并显式写明切换模式
   （`CONTENT_FIRST`：先把目标页内容备好再过渡，避免"滑过去先看到一片空白"）；
5. **深浅色都可读**：骨架色是新的语义色，两份主题都要给。

**不做（范围外）**：

- **不做"骨架的像素级还原"**（按每页真实行的字号/间距/圆角逐一复刻）：骨架表达的是
  "这里将出现一列这样的东西"，不是内容预览。逐页复刻的维护成本远高于收益，
  故四个页面共用**一套**行形状；
- **不做列表项的入场动画**（逐条淡入/位移）：那要把 store 回调包进 `animateTo`，
  为一个观感项把数据流改脆弱不划算；
- **不做骨架的滚动与交互**：占位块不响应滚动——它是占位，不是内容；
- **不做页面切换的自定义转场**（`Navigation`/`NavDestination` 自绘转场）：
  系统默认转场已经成立，自绘要接管返回手势等一整套行为，不是本 FR 的量级。

## 3. 设计（怎么做）

### 3.1 上游事实（对照基线）

| 事实 | 出处 |
|---|---|
| 上游的 `Skeleton` 是**一块**四根灰条（宽 30%/100%/80%/20%，高 16、圆角 4、外边距 12/16），整块做 1 ↔ 0.5 的循环呼吸 | `src/components/Skeleton.tsx` |
| 上游只在**文件详情页**用它（一块块堆出信息区），**列表加载**走的是列表自己的 `refreshing` | `src/screens/FileDetail.tsx` |

> 与上游的**有意不同**：把骨架用到**列表**上是本项目的做法（FR-29 的要求）。
> 呼吸动画与"灰条＝占位"的语义则与上游一致。

### 3.2 模块与文件

| 层 | 文件 | 职责 |
|---|---|---|
| `components` | `Skeleton.ets`（新） | `SkeletonList` 组件：N 行灰条 + 呼吸动画 |
| `components` | `StateView.ets`（改） | 注释指向新组件；`loadingView()` 保留给非列表场景 |
| `pages` | `Notices.ets` / `Assignments.ets` / `Files.ets` / `Courses.ets`（改） | 加载分支换成 `SkeletonList({ rows: 6 })` |
| `pages` | `Main.ets`（改） | `Tabs` 显式 `animationDuration` 与 `animationMode` |
| 资源 | `base` / `dark` 的 `color.json` | 新增语义色 `skeleton` |

### 3.3 关键规则

1. **骨架是 `@Component` 而不是 `@Builder`**：呼吸动画需要自己的一份状态（`StateView.ets` 里的
   三个状态是纯展示，所以用 `@Builder`）。这里的取舍写在组件注释里。
2. **呼吸用一次 `animateTo` + `iterations: -1` + `PlayMode.Alternate`**，而不是递归 `onFinish`
   （递归版本在组件销毁时还要自己收尾；无限往返由平台管）。参数：`duration = 500ms`、
   `Curve.EaseInOut`——与上游"500ms 一来一回"同量级。
3. **灰条数量与高度对齐真实行**：每行三根（16 / 14 / 12），宽度 60% / 100% / 40%——
   宽度是"文字长短的示意"，不必精确。
4. **骨架带上稳定标识**（`.id('listSkeleton')`）：骨架是**瞬时**状态，靠 `ui layout` 抓拍很难
   撞上；有了标识，节点树里一条 `id` 就能判定"此刻渲染的是骨架而不是转圈"。
   这是 ArkUI 的正常属性（组件标识），不是为测试加的特例代码。
5. **`animationDuration` 是常量**：200ms 与系统其他过渡同量级；写常量并注明理由，
   免得以后被当成魔数改掉。

## 6. 风险 / 待定

| 项 | 说明 | 处置 |
|---|---|---|
| 骨架在预载生效后可能"一闪而过" | FR-25 把通知/文件提前到启动预载，用户切到这两个标签时数据往往已就位，骨架可能根本看不到 | 属正常结果（骨架是兜底，不是必经）。**实测确实如此**：验收只能用临时探针构造（§5 第 5 条），已写明方式 |
| 无限动画的开销 | 骨架带 `iterations: -1` 的无限动画 | 只在加载态存在（数据到位即销毁组件），不会常驻；若发现耗电再改为有限次数 |
| 动效本身**无法从节点树判定** | 过渡与呼吸是"看不见的"，日志与节点树都不反映 | 本 FR 的动效部分**如实标未验证**（只保证编译通过、装机运行不崩），观感需用户真机确认 |
