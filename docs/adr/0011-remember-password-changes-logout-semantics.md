# ADR-0011：「记住密码」改变登出语义——勾选后登出保留凭据

## 状态

已接受（2026-09-27 用户决定，2026-09-28 落地实现，见 PRD FR-31）

## 背景

`docs/SECURITY.md` §2 原先规定：**用户改密或登出时，加密存储中的学号与密码必须清除**。
这条规则的目的是"在共用或丢失设备上，登出之后不再留下可直接恢复登录态的东西"。

而产品侧的目标语义（PRD FR-31，用户 2026-09-27 明确）是：**勾选「记住密码」后，登出仍保留
学号与密码（密码继续走加密存储），下次打开应用可直接恢复登录态；未勾选则登出即清除**。

两者在"勾选时登出要不要清除"这一点上直接冲突。PRD 已把该变更排在**所有 P1 功能之后**，
并要求**同批修订 `SECURITY.md` §2 并写 ADR**——`SECURITY.md` 原文里也留了同样的前瞻说明
（"在落地之前本条仍然有效——不得先改代码后补规则"）。本 ADR 即那次修订的一部分。

## 决策

1. **凭据处置按用户的选择分流**，判据是"密码是否在加密存储里"：
   - 勾选「记住密码」→ 登出**保留**学号与密码（密码仍在加密存储中，**不落明文**）；
   - 未勾选 → 登出**清除**学号与密码（原语义）。
2. **不新增"是否记住"的独立开关**：`CredentialStore.save(credentials, rememberPassword)`
   已经用"写不写密码"承载了这个选择，再存一个开关就是第二份可能与它不一致的状态。
   密码缺失时按"未记住"处理——**保守方向**（清除）。
3. **设备指纹永不清除**：它是设备标识而非凭据（沿用 2026-09-27 的既有更正，见 §2 的例外说明）。
4. **"登出成功"的判据随之改写**：从"凭据已清除"改为"凭据已**按策略处置**"。
   于是 `LogoutResult.credentialsCleared` 更名为 `credentialsHandled`，`common/logout.ets`
   的判定与文案不变，只是"保留"这一合法结果不再被误判为失败。
5. **规则范围**：`SECURITY.md` §2 的那条改为"**未勾选记住密码时**，学号与密码必须清除"，
   并写明勾选时的保留与它的前提（密码仍加密存储、用户可随时取消勾选）。

## 后果

**接受的风险**：

- 勾选「记住密码」的用户，其凭据在登出后仍留在设备加密存储中；**能解锁设备的人可以直接
  恢复登录态**。这是用户明确选择的行为（"下次打开可直接恢复"），也是目标语义的全部意义所在。
- 与"共用设备"场景的期望相反：共用设备的正确用法是**不勾选**。设置项与登录页的措辞
  必须让这一点可被理解（登录页已有该勾选项，其含义现在需要成立）。

**缓解措施**：

- 密码**始终**存于系统关键资产存储（加密），不落明文、不入日志、不进代码（ADR-0007 不变）；
- 不勾选时行为与原先完全一致，即"登出即清除"仍是默认语义（登录页默认勾选——
  与上游一致，但这意味着**默认即保留**，故本条的措辞与提示必须清楚）；
- 取消勾选并重新登录后，密码别名会被移除，下次登出即清除。

**遗留**：

- 界面上目前只有登录页的勾选框表达这一选择，**没有任何地方显示"你的密码仍保存在设备上"**。
  这属"清晰告知"的缺口：本次未加（避免在本批引入新的设置项与文案），登记为后续增强
  （与 FR-16 的设置页合并考虑：设置页可以显示当前是否处于"已记住"状态并提供一键清除）。
  在此之前，`SECURITY.md` §2 的措辞与本节即为该行为的书面记录。

## 备选方案

- **保持原语义、不做 FR-31**：与用户明确的产品决定冲突（FR-31 是 P1），否决。
- **存一个独立的"记住"开关**：两份状态可能与密码别名不一致（例如密码写入失败但开关已置），
  需额外的对账逻辑，否决。
- **登出保留但下次启动需要生物识别解锁**：属 FR-24（P2），当前不做；将来若做，
  它正好补齐上面那条"遗留"的风险缓解。
