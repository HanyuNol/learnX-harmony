# 验证门与质量底线（防质量漂移）

> 项目特定的测试与质量要求。通用反模式禁令（上帝类、长方法、复制粘贴、魔法值、吞异常、资源泄露、循环依赖、静态可变单例等）仍然适用。

## 1. 验证门（权威判据）
- **每个变更必须过验证门才算完成**，判据以**入库真源**为准：① `docs/PRD.md` 验收标准对应项满足；② 本文 §2 高风险区相关测试通过；③ 受影响组件全部测试绿（各组件按本项目实际的测试 / 构建命令执行）。
- **完成以证据为准、不轻信报告**：声称"做完 / 修好 / 通过"前，必须出示上述各项的客观证据（命令 + 关键输出、失败用例从红转绿、有实机 / 集成 / 真实环境维度的附该维度复验结果）。拿不齐 = 未完成、继续做——不轻信任何"完成了"的口头报告（含子代理的汇报）。
- **被推翻就回流继续修**：声称完成后被实测 / 实机 / 用户验收推翻，即视为该变更未完成，**回到本任务对应技能的验证步骤继续修**，不另开新流程、不重标状态。
- **提交受验证门门控**：验证门未全绿不得 `git commit`（门控见 `git-commit.md` §3）。
- `.tmp/` 下实施计划的里程碑勾选**仅作开发期辅助**，不入库、不作权威判据（clone 后可能不存在）。
- **禁止**以注释、跳过、删除失败测试的方式让测试"通过"。
- 改功能代码前先跑相关测试确保通过；新增 / 改业务逻辑同步加测试。

### 1.1 测试分层（怎么分、在哪跑）

- **单元（Local Test）**：纯逻辑（核心算法 / 纯函数）—— 不连外部依赖，最快最多。
  本项目的执行方式：`hvigorw test`，在 `app/` 下运行，**宿主侧执行、无需设备/模拟器**。
  用例放 `entry/src/test/`，并**必须在 `List.test.ets` 中登记**，否则被静默跳过。
- **集成 / 实机**：依赖系统能力的代码（网络、凭据存储、页面）宿主侧跑不了，
  需设备或模拟器。**在此之前，这些模块的正确性属未验证。**
- **何时跑**：单元测试随每次改动；实机验收在对应 FR 交付前至少跑一遍。

#### 两条硬性陷阱（本项目实测）

1. **测试失败不会让构建失败**：用例失败时输出 `ERROR: Error in <用例名>`，但末尾仍是
   `BUILD SUCCESSFUL`。**退出码不可作为测试门禁判据**，必须读结果文件
   `entry/.test/default/intermediates/test/coverage_data/test_result.txt`（逐用例 Success/Failure）
   与 `entry/.test/default/outputs/test/reports/coverageReport.json`（覆盖率）。
2. **`devecocli check arkts` 默认不扫描 `src/test/`**：它会报"零错误"而测试文件根本没被检查。
   改动测试后必须显式传路径复查，否则"零错误"是空检查。

#### 纯逻辑必须与平台调用分离

凡与外部服务互操作、且不依赖系统能力的逻辑（密文格式拼接、页面正则抓取、协议解析），
**必须单独成模块并保持零系统 Kit 依赖**，否则在无设备环境下完全无法验证。
本项目此类模块：`network/sm2Format.ets`、`network/parse.ets`、`network/cookieJar.ets`。

> 覆盖率的边界要说清：Local Test 的覆盖率只统计**测试导入到的文件**。
> 报出的百分比**不等于**全应用覆盖率——不得把"某子集 76%"说成"应用覆盖率 76%"。

## 2. 必测的高风险区
1. **凭据与 Cookie 的写入与清除**（泄露即安全事故）。穷举：登录成功/失败、登出、改密、认证失效各路径下，加密存储的写入与清除是否成对；`common/` 日志与崩溃路径输出中不含凭据或 Cookie；仓库与缓存中无明文凭据。
2. **会话状态流转与 CSRF**。穷举：未登录 / 已登录 / 令牌过期 / 失效期间发起请求的结果；CSRF 令牌的获取-注入-刷新是否覆盖写操作。
3. **错误四分类（网络不可达 / 认证失效 / 接口语义变更 / 解析失败）**。穷举：为每类构造输入，断言归类正确且**不得互相误报**（尤其网络问题不得报成应用缺陷）。
4. **网络失败下的缓存退让**。穷举：无缓存首次进入 / 有缓存可用 / 仅部分维度失败 / 全部失败四种情形，均不得白屏。
5. **Store 订阅生命周期**（ADR-0004 已明示的内存泄漏风险）。穷举：页面进入 → 退出 → 重复进出后，订阅计数必须归零；组件销毁后不得再收到回调。
6. **文件下载与本地路径**。穷举：外部传入的路径越界被拒（目录穿越）；下载中断可重试且不残留半截文件；同名文件不静默覆盖。
7. **系统能力授权被拒**（日历 / 通知 / 生物识别）。穷举：拒绝授权后，主流程（浏览数据）必须不受影响，仅在设置页提示。
8. **HTML 清洗与 WebView**。穷举：`<script>`、事件属性（`on*`）、`javascript:` 链接被剥离或拒绝执行；统一身份认证 WebView 中不注入任何脚本。

> 上述 1、2、7 的最终判据包含**实机 / 真实环境维度**，须按 `docs/PRD.md` §6 由用户确认，单元测试绿不能替代。

## 3. 质量底线
通用反模式底线（任何项目都适用）：
- 分层依赖单向、不反向穿透（防上帝类 / 防泄漏底层细节到上层）。
- 锁 / 临界区职责单一、不嵌套，高开销 IO 一律在锁外。
- 核心计算尽量做成无副作用纯函数，便于穷举测试。
- 多处写操作必须在事务内原子完成，**事务提交成功后**才触发对外副作用（通知 / 唤醒 / 发事件）。
- 中文分级日志（ERROR/WARN/INFO/DEBUG），不留 `println` / `console.log` / `fmt.Println` 等临时调试输出。
- 不硬编码凭据 / 端口 / 超时等，走配置或常量。

> 以上为通用底线；请按本项目的架构不变量与领域特性补充更具体的质量条款（如特定的分层名、特定的并发/锁约定、特定纯函数边界等）。
